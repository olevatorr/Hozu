# Languages

- **The URL holds the language:** `site: { lang: 'en', locales: ['en', 'de'], … }` keeps `/posts/a` for `en` and
  prefixes the others (`/de/posts/a`). Routes and `ui.link` stay locale-free. No cookie, session field or rewrite.
- Switch: `ui.a({ href: ui.alternate('de') }, ['Deutsch'])`.
- `export const text = ui.messages('en', { en: { saved: '{count} saved' }, de: { saved: '{count} gespeichert' } })`
  in a listed module; `text.saved({ count })` in views. Every locale needs every key (HZ040).
- Machines never hold translated text (HZ041): store a code.
- **Data per language:** `locale` (in every view, 2nd argument of `head.input`, 3rd of `head.render`) goes into
  the query input: `ui.query(listPosts, { locale })`; `head: { input: (params, locale) => ({ slug: params.slug,
  locale }) }`. It is typed `string`: declare the input `z.string()`, or narrow it with `locale as Locale`.

## Details
- Reload, sign-in and sign-out keep the language, because every link and `navigate` resolves `ui.link` in the
  page's locale.
- `/en/posts/a` answers 308 `/posts/a`. There is no `Accept-Language` redirect: a new visit to an unprefixed URL
  shows `site.lang`. Contracts expect the default URLs. `<html lang>`, hreflang and the sitemap are derived. A page
  route starting with a locale segment is HZ060.
- A toggle: `locale === 'en' ? ui.alternate('de') : ui.alternate('en')`.
- Messages: use `text.title` or `text.saved({ count })` in views and `head.render`; every locale needs the same
  `{placeholders}` (HZ040). Plurals: `'{n, plural, =0 {none} one {# item} other {# items}}'`.
- Machines store a code and the view chooses the message.
- `ui.format.number(x, { style: 'currency', currency: 'EUR' })`, `ui.format.date(x, { dateStyle: 'medium' })`,
  `ui.format.relative(n, 'day')`, `ui.format.list(xs)`, `ui.format.plural(n, { one: '# item', other: '# items' })`.
  `locale` is in every view.
- Head signatures: `input: (params, locale, search)`, `render: (data, params, locale, search)`.
- Resolvers have no locale of their own; it reaches them only through the input. The sitemap lists one entry per
  `entries` input in every locale.
- `ui.format.date` takes an ISO string or a timestamp and formats it in the page's locale, in the time zone of the
  machine that renders it. A date without a time (`'2026-09-12'`) is midnight UTC: pass `{ timeZone: 'UTC' }` so
  every server and browser shows the same day.
- A form's `Invalid` messages come from the schema in one language: store `invalid: true` (or a code) in context and
  choose the text in the view.
