# Change request 23 for the notes app

The app in this directory already implements the notes app. Everything it does today must keep working, with and
without JavaScript, unless this request changes it. Change the following.

## Edit a note on its page, with a body
- A note now also has a **body**: free text that is empty for every existing note and every newly added note.
- The page of a note that is not archived gets a form with a text input with the accessible label `Title` holding
  the current title, a multi-line text field with the accessible label `Body` holding the current body, and a
  button `Save`. The browser limits the fields: `Title` is `required` with `maxlength="60"`, and `Body` has
  `maxlength="1000"`.
- `Save` checks both fields on the **server** and saves only when both are valid:
  - the title follows the rules of adding: trimmed, 1–60 characters, and not the title of another of the user's notes
    (case-insensitive, archived notes included). The messages are `Write a title first`, `Use at most 60
    characters` and `You already have a note with this title`;
  - the body is trimmed and at most 1000 characters; a longer body gives `Use at most 1000 characters in the body`.
    Line breaks inside the body are kept.
- When anything is invalid, nothing is saved, every message that applies is shown, each in its own element with
  `role="alert"` (a title message and a body message can show together), and both fields keep exactly what the
  user typed.
- After a successful save the page shows the text `Saved` in an element with `role="status"`, the new title in the
  `<h1>`, and the body with its line breaks. The note keeps its number, place in the list, pin and `Added` date.
  A save is a change to the user's notes: it ends an `Undo` message, like `Edit`.
- The page of an archived note shows its body but no form, and the **server** refuses to save an archived note.
- All of this also works with JavaScript disabled.
