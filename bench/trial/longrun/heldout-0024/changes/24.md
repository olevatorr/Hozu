# Change request 24 for the notes app

The app in this directory already implements the notes app. Everything it does today must keep working, with and
without JavaScript, unless this request changes it. Change the following.

## Read-only accounts
- The admin can make another user's account read-only, and writable again. The table on `/admin` gets a third
  column with the header cell `Access`; in each row that cell starts with the text `writable` or `read-only`.
  The row of every user other than `admin` also has a button `Make <name> read-only` (for a writable account) or
  `Make <name> writable` (for a read-only one). The `admin` row has neither button.
- Only the admin can change this: the **server** refuses it for anyone else.
- While an account is read-only, its user can still sign in and out, read and search their notes, use `Load more`,
  open note pages, export, and delete their account. The **server** refuses every other change to their notes:
  adding, editing (on the list page and on the note page), deleting, `Delete selected`, `Undo`, pinning,
  archiving, `Archive selected`, restoring, sharing and unsharing. Nothing changes, and the page the user ends up
  on shows `Your account is read-only` in an element with `role="alert"`.
- The list page of a read-only user shows the text `Read-only account`.
- It affects no one else: notes the user shared stay visible to the users they were shared with, and the user still
  sees the notes shared with them.
- The setting is kept on the server and survives signing out and in. Deleting the account ends it: the same name
  signing in again starts writable.
- Making an account read-only or writable also works with JavaScript disabled.
