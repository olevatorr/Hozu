# ADR 0083 — 0.29: what the Mori rebuild and the DevTools trial met

- **Status:** accepted (owner, 2026-10-10: "請你直接做到完，都以你建議為主").
- **Evidence:**
  - the Mori public site rebuilt on 0.27 (ADR 0080 B; 25 pages, pixel difference ≤ 2.05 %, 19 frictions F1–F19);
  - trial 0023 (`docs/trials/0023-devtools.md`; findings D1–D6).
  Each item was reproduced on the 0.28 source before it was judged.
- **No breaking change.** `hozu migrate` 0.28 → 0.29 rewrites nothing. A kit whose `tv.ts` now lists more classes
  reports HZ078, and `hozu add kit <id> --sync` updates it.

## Accepted
| # | Ask | Decision |
|---|---|---|
| A1 | F14: a fixed mobile menu inside a shared header was drawn under the page | A `view-transition-name` makes its element a stacking context, so a `fixed z-[70]` drawer inside it could not rise above later content. `@hozu/css` now names shared views only while a transition runs (`:root:active-view-transition [data-hz-view=…]`), on both the old and the new page. Browsers without the pseudo-class get the root cross-fade without named parts |
| A2 | F15: tailwind-merge dropped the project class `text-mini` | A plain stylesheet class whose name begins with a Tailwind functional root (`text-`, `bg-`…), and which Tailwind does not itself generate, is its own class group in the generated config (`lookalikes` in `@hozu/css` tokens) |
| A3 | F13: `price * quantity` | `*` and `*=` lower to the operator builtin `%times` |
| A4 | F5: HZ079 for `{ a: isPicked(x), b: !isPicked(x) }` | `exclusive()` matches a `fn()` result against its negation in both lowered forms |
| A5 | F1: `ui.set(ctx.open, false)` inside `ctx.open && …` did not type-check | A boolean field takes any boolean. Enum fields still take only their members: TypeScript cannot recover the declared type from a narrowed reference, and HZ031 checks the literal at build time |
| A6 | F9: `ui.each` items could not return `null` | The item render may return `null`, as `ui.query`'s `ready` already may. The build already lowered it to an empty branch |
| A7 | F3: CMS images of unknown size | HZ028 accepts an `img` whose own classes, without a variant, fix both width and height, or an aspect ratio and one of them. This is read from the CSS stage, so a check without styles still asks for the attributes |
| A8 | F12: reading a field of a `fn()` result | The HZ059 cause says to make the `fn` return the value needed; the feature topic says the same. No field access on call results (one canonical form: a `fn` computes, a reference reads) |
| A9 | F16: "no control named password" | This could not be reproduced with pure components. The likely case is a client component, whose fields are opaque, so HZ063 now names it in the message and its fix says to render the control outside the client component |
| A10 | F10, F18 | Recipes: a layout helper writes `head` inside its `ui.page` call (a separate object loses the query type); a notice on the next page is an enum search field the page maps to words |
| A11 | F19: `press PageDown` failed; external images were missing from screenshots | `press` knows PageUp / PageDown / Home / End / Insert / Delete / F1–F12. The images were blocked by the app's own CSP, as they would be in production: browse adds the fix `app({ csp: { img: ['<origin>'] } })` to that error, rather than letting them through |
| A12 | D1: a style request said "change the data, not the view" | A request that only changes style says that the classes change in this view and the data stays |
| A13 | D2: "at an unknown place" | Copies of a shared `on` have their source location, and the behaviour line names the shared entry once with the states it is copied into. A list fed through a `fn()` finds its query |
| A14 | D3: the Workbench laptop was the default viewport | The presets are Laptop 1366 × 768 and Desktop 1920 × 1080. A request made in the Workbench names its device and the browse command that checks it |
| A15 | D4: HZ018 asked for a contract per copy of a shared `on` | The lock review groups the copies of one entry: one contract covers them, and an unspecified entry is reported once at its source. HZ016 reports an uncovered shared entry once as well. The skeleton both print starts from values that satisfy the guard (`contracts/solve.ts`: `===`, `!==`, comparisons, truthiness, `and` / `or` / `not`; earlier guards of a list are made false) |
| A16 | D5: `click "Remove"` hit the covered row under a full-screen overlay | When a name matches several controls and some are inside the top layer (a modal dialog, `role=dialog`, or a fixed element covering the viewport), browse uses those. A covered click names the overlay by its heading |

## From the review before the tag
- HZ018 grouped copies by their lock fields, and the copies of a shared `on` that stays differ in `enters` (each its
  own state): a staying transition is grouped without it.
- Browse preferred any `role=dialog` or full-screen fixed ancestor, so a hidden menu could win: an overlay is preferred
  only where `elementFromPoint` at the control lands inside it.
- `hozu check` read lookalike classes from the CSS with the app's classes, `--sync` from the stylesheets alone, so an
  arbitrary variant such as `[&_.text-label]:mt-2` left HZ078 unfixable: both read the stylesheets alone.
- The skeleton solver joined conflicting values for one field (`x !== 'a'`, `x !== 'b'`, then the fallback); it now
  gives up and prints the plain skeleton.
- HZ028 no longer counts `fit-content` / `min-content` / `max-content` or a percentage height as a fixed size; a
  `100%` width counts only with an aspect ratio.
- B2 (one CPU-throttled run) read 60.8 and 64.7 ms against 50 at load average ≈ 9–11. Interleaved runs of 0.28.0
  and this release on the same machine: 71.1 / 57.7 / 48.6 / 51.4 ms against 54.0 / 46.8 / 55.7 / 47.4 ms. No
  runtime-client code changed, so it is recorded as unstable under load, not as a regression.

## Declined
| Ask | Why not |

| F7 / F8: open head fields, a title template, custom JSON-LD | The head is a closed set by design (ADR 0043 D). Structured data per type (Product, FAQ, Breadcrumb) needs its own design after 1.0, so it is recorded, not built here |
| F11: a page-level client hook | Closed world: JavaScript runs in a declared client component (ADR 0045) |
| F17: `head.failed` to a route with parameters | Recorded for the post-1.0 head design together with F7 |
| F6: a single node as `<svg>` children | One canonical form: children are a list |
| F2, F4 | Working as designed (hooks use `data-*`; `feature({ styles })` is a list, HZ014) |
| D6 | Trial design, recorded in ADR 0048 |
