### A3: a computed `noindex`
| Option | What | For | Against |
|---|---|---|---|
| **A3a (recommended for 0.27)** | `noindex` may be computed like `title`: `HeadIR.noindex` becomes a value expression, evaluated per request; the sitemap leaves a page out only for a literal `true` and lists a computed one by its entries | Small; consistent with the other head fields; the notice pattern works today | A notice URL is still its own cache entry and its own canonical |
| A3b (later, with the kit's notices) | A **transient** search field: `search: { notice: transient(z.enum([...])) }`, left out of the canonical URL and the cache key, the page `noindex` while it is present | "A notice is not a different page": one canonical, one cache entry | A new authoring form (principle 1: it must be the one way); needs its own ADR |

Recommendation: A3a now, and an error instead of silence for any head field that cannot be computed.

## B. The same-place swap (round 9) — corrected
ADR 0078 recorded that the new row "fades in as an added row". **That was wrong.** The keyed list update in
`packages/runtime-client/src/mount.ts` fades the new rows only when no row left in the same update
(`!node.motion && !old.size`); five steps becoming two remove four rows, so nothing fades and nothing blinks. B1
("a same-place swap does not fade") is how the runtime already behaves.

What the admin saw is the browse report: the new row's unchanged child (`<span>Priya</span>` in the repro) sits
where the removed row's identical child was, and `smoothness()` counts it as "rebuilt unchanged". The detector
cannot tell that from a real rebuild of the same node (the `click Toggle` case in `browse.test.ts`, the shape of
ADR 0069 A3), because it does not see keys. A rule that guessed from the DOM (the 0.27 draft tried "count it only
when the whole inserted subtree matches") lost that real case, so it was reverted.

- **Decision:** no change in 0.27. A key-aware report needs the runtime to tell browse what a keyed update inserted
  and removed; that is its own small ADR, when an app needs it. Until then the guide says: a flash inside a list
  whose rows changed keys may be a different row with the same content.
