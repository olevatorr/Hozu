# ADR 0070 — 0.23: the 0.22 trials, the Go trial, and what stays hard

- **Status:** accepted (owner, 2026-10-08: "照建議，全部做完發佈"; before: "B" — everything from the 0.22 retest goes into 0.23 — and "A": the admin
  agent moves part of its backend to Go before 0.23 is decided). Sections A are done on `release/0.23.0`; B and C list
  decisions for the owner.
- **Evidence:** both trial agents upgraded to 0.22.0 with `hozu migrate` (0 files rewritten, IR equal) and retested.
  Admin: framework friction from 20–30 % to 10–15 %. Storefront: 13 of 21 pain points fixed, 4 partly; retest from
  about an hour to 15 minutes. Both would choose Hozu again.

## A. Fixed (bugs the retest found)
| # | Problem (who) | Cause | Fix |
|---|---|---|---|
| A1 | The canonical URL of `/shop/:category?` carried every default (`?availability=all&page=1&…`), and links built from search values did too (store; since 0.17) | The route table spells a route with defaults `/shop/:category??sort=featured`; `pathOf` split at the first `?`, the optional modifier, and lost the defaults | `pathOf` splits at the `?` that starts `key=value` pairs (or ends the pattern). Test with an optional segment |
| A2 | `params: z.object({ id: z.coerce.number() })` typed `id` as a number, but resolvers got the string (admin) | Route params were checked against the schema, never parsed | The router parses params (`bindings.parses['#route:…']`): coercions and defaults apply, like query inputs |
| A3 | `aria-current="true"` on a next-page link (same path, other search), read as "current" by screen readers (admin) | 0.22 counted the same path with another search as the section | Only a path above the page is a section; another search gets nothing; an author's `aria-current` wins (documented) |
| A4 | The same server error printed twice (a head and a view reading one query) (admin) | One line per call | `get` / `browse` print each distinct error once per step |
| A5 | Docs: a machine-bound dialog needs JS while the guide's short form shows the native `commandfor` one; "A database" was not findable from SKILL.md; the multi-step recipe missed the edit-back step (both) | — | Views topic says which needs JS; SKILL.md's `data` row says "a database"; the recipe covers going back |

## B. Asked for, to decide
| # | Ask (who) | Options | Recommendation |
|---|---|---|---|
| B1 | Keep a multi-step form's state across native posts without hand-written hidden fields (both; ~40 lines in the store) | (a) the server signs the machine snapshot into a hidden field of every form it renders natively, and restores it on the post; (b) keep the recipe | (a): one hidden `__hozu_state` (HMAC with the session secret, size-capped), only on forms whose submit starts from a non-initial state |
| B2 | `ui.link(route, params, { ...search, page })` to keep the current search (admin) | (a) lower object spread of a `search` reference in the transform (`%merge`); (b) `ui.link(route, params, search, { page })` | (a): the TypeScript spelling agents already write |
| B3 | `{ allow }` that reads `session.role` still types `session` as nullable (admin) | (a) every access but `'anyone'` types `session` as present (the runtime already refuses a null session for them); (b) only `'signedIn'` | (a) |
| B4 | `app()` cannot read env, so session stores read `process.env` (store) | `app(({ env }) => ({ … }))` as a second form; or `env` passed to the session store factory | **Docs:** a second form of `app()` would be two spellings; on Node `app.ts` reads `process.env`, on Workers the host passes `createHandler(app, { session })`, and a pool is made lazily from `ctx.env` in the resolvers |
| B5 | Lock lines of a changed transition are ~1 KB (store) | print only the changed assignments (ADR 0067 J did it for fields, not for `assign` lists) | yes |
| B6 | `--js both` reports `DIFFERS` when each mode writes its own row (an order number) (store) | name the differing words; or a per-mode database is the app's business | name them and say so in the testing topic |

Done on `release/0.23.0`: B1 (`__hozu_state`, HMAC with `SESSION_SECRET` or a per-process key made on first use,
16 KB cap, only on forms rendered after a native post), B2 (`%merge`), B3, B5 (a `now:` longer than 120 characters is
left out), B6 (`work/023-go`).

Kept as they are (ADR 0069 C): more than one machine per feature, parts across features, arbitrary methods in
views, a global toast store.

## C. The Go trial
The admin agent moved 10 effects (the order lifecycle with restock in one transaction, inventory with its ledger,
the dashboard statistics) to a Go service with `remote()` and the shared MySQL: 1 334 lines of Go plus 260 of tests for
734 lines of TypeScript; the first `go build` passed; `hozu call --json` gave byte-identical answers for 7 compared
calls; a storefront order went through pack, ship and refund with restock. Access, Invalid and the output check
stayed in Hozu as designed. Its verdict: keep TypeScript unless a Go service exists or a measured need asks for Go.

| # | Problem | Decision |
|---|---|---|
| C1 | A service that is not running answers `fetch failed`, without the URL or the effect | The error names the effect and URL and says to start the service |
| C2 | A Go error reaches Hozu as `answered 500 resolver failed`; the cause is only in the Go log, with nothing to match | Each call carries `x-hozu-call: <id>`; the Go handler logs it and answers its error's first line, which reaches `onError` (as a thrown TypeScript error does) |
| C3 | One fingerprint for the whole contract: changing one effect makes every effect answer 409 | A fingerprint per effect (in the contract and per call); the session shape is part of each |
| C4 | `z.number()` becomes `float64`, so ids are floats until the schema says `z.int()` | `hozu gen` names number fields that look like ids or counts and suggests `z.int()` |
| C5 | `examples/notes-go` is in the repository, not in the packages | The guide links it and shows the `main.go` it needs (env, secret, shutdown) |
| C6 | Enums are `string` with a comment | `type OrderStatus string` with one constant per member, for titled enums |
| C7 | A wrong output repeats one issue per row (10×) | Issues that differ only by an index are printed once (`rows.*.tone (10×)`) |
| C8 | `hozu browse` marks a native `commandfor` button `js-only`, though Chrome opens the dialog without JS | Buttons with `commandfor` are native, not js-only |
