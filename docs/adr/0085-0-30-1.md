# ADR 0085 — 0.30.1: what the Mori Docker rehearsal met

- **Status:** accepted (owner, 2026-10-10: "請你直接做到完，都以你建議為主"; "請繼續").
- **Evidence:** the Mori public site and back office ran from `hozu build --target node` images with
  `docker run` (ADR 0080 B). Both containers stopped at start, each for a reason no command had named.
- **No API change.** This is a patch release: `hozu migrate` raises the packages and rewrites nothing.

## Accepted
| # | Found | Decision |
|---|---|---|
| A1 | `Cannot find package '@hozu/bundle' imported from /app/app.ts` | `create-hozu` lists `@hozu/bundle` under `devDependencies`. `hozu add component --client` added it to `dependencies` but left the dev entry, and `npm ci --omit=dev` installs neither when a package is in both. The command now moves the entry, and `--target node` lists under "the platform needs" any package that is in both |
| A2 | `Can't resolve '@tailwindcss/typography'` | `hozu serve` compiles the stylesheets at start, so a package they load (`@plugin`, `@import` by name) must be a dependency. `--target node` names one that only `devDependencies` list |

After both fixes, the rehearsal passed:
- the public site answered its pages from the container, and a member signed in through the native form;
- in the back office, staff signed in without JavaScript and were sent away from admin-only pages, as on the
  original site.

## Declined
| Ask | Why not |
|---|---|
| Put `@hozu/bundle` in every app's `dependencies` | Most apps have no client component and would install esbuild in production for nothing; A1 moves it when the first client component is added |
