# ADR 0076 — 0.26.3: an upgrade within a minor raises the packages, and the tools say which version they check

- **Status:** accepted (owner, 2026-10-09: "Ok都照你建議").
- **Evidence:** round 7 of trial 0025 (admin and storefront on 0.26.2). Both agents ran `npx hozu migrate` from 0.26.1:
  it compared minors only (0.26 = 0.26), left `@hozu/*` at `^0.26.1` with 0.26.1 installed, and went straight to
  `verify` against `.hozu/migrate-0.26.json`, a record saved at the 0.25 → 0.26 migration and never removed because
  that verify had found differences. The 0.26.2 CLI then checked the 0.26.1 packages (688 and 216 errors) and listed
  the agents' own edits since 0.25 as undeclared behaviour changes. Both: "following the tool, you would think the
  framework is broken".
- **Judged as before:** whose problem, which principle. Items 1–3 are bugs; 4–9 break principle 7 (a diagnostic
  names its place, cause and fix, and says nothing false).

## Accepted
| # | Ask (source) | Decision |
|---|---|---|
| A1 | `migrate` does not raise a patch upgrade (both) | Versions compare in full. A CLI newer by a patch is phase `upgrade`: no source rewrite, `@hozu/*` raised to `^<cli>`, and `next:` says install, then `hozu check` |
| A2 | A stale record is compared (both) | A record names the exact version it was written for (`version`). `verify` runs only when that version is installed; any other record (or one without `version`, written before 0.26.3) is stale: it is removed with a note saying so |
| A3 | `check` with a CLI and packages of different versions (admin) | `hozu check` fails first with the two versions and the fix (`npx hozu migrate`, then install); its other diagnostics follow, marked as possibly caused by the difference. `CheckOutput.versions` holds both |
| A4 | "Workers has no Node built-ins" is too absolute (both) | The message says what the build does: it bundles no Node built-ins (Cloudflare's `nodejs_compat` stays off, ADR 0075) |
| A5 | An existing `Dockerfile` / `.dockerignore` is kept silently (admin) | Each kept file is listed (`kept .dockerignore`), and the lines the generated `.dockerignore` would add that the kept one lacks are named |
| A6 | `--target node --out` prints a misleading `docker build` (both) | The build context is the app: `docker build -f <out>/Dockerfile -t app <app>`, with paths relative to where the command ran. The ignore file is `<out>/Dockerfile.dockerignore`, which Docker reads next to that Dockerfile (a `.dockerignore` there would be ignored, and `.env` copied into the image) |
| A7 | A failed `--target vercel` leaves an empty `.vercel/` (store) | A failure removes every folder the build created, not only the output |
| A8 | Focus notes cannot tell two `name="q"` fields apart (both) | The note adds the accessible name (`aria-label`, its label, `placeholder`); `press` always reports focus: moved, stays, or left |
| A9 | A shortcut whose control is hidden does nothing silently (store) | `press` says `no visible control has <key>` when only hidden controls declare it |

## From the review before the tag
- `hozu check --update-lock` does not write the lock while the versions differ, and the fix follows the direction
  (an older CLI: `npx -p @hozu/cli@<core> hozu check`). Pre-releases compare in order (`rc.2` < `rc.10` < release).
- A record stays valid within its minor until it was verified once: a patch installed between the rewrite and the
  verify (`^` ranges) does not discard it; a record verified on another version does not come back. The record keeps
  `verified: <installed>` after a verify that found problems.
- A press that loads another document reports no focus; focus is read after the page settles. Keys compare as the
  runtime does (`Mod` = `Meta` on macOS, modifiers in any order), inside an open modal dialog.

## Declined
| Ask | Why not |
|---|---|
| Chains start at `app.ts` (admin) | The first app file that imports the module is where the fix goes; the entry adds length, not information |
| Factory functions, more machines per feature, kit components taking data objects (store, again) | Unchanged reasons (ADR 0069 C, ADR 0070 B4, ADR 0075) |
