# ADR 0052 — 0.13: environment conventions (`env.files`, `env.internal`, `hozu env`)

- **Status:** accepted (owner, 2026-10-03). All five items. `env.files` defaults to `['.env', '.env.local']` in new
  apps. `hozu env` is its own command. Without an internal URL, the public one is used.
- **Problem:** typed env (ADR 0019) is a good base: `project({ env: { server, public } })` is parsed at startup.
  Around it, five things are missing.
  1. **No env files are read.** `hozu dev`, `check`, `get` and `call` see only the shell, so a `.env` an agent
     writes silently does nothing.
  2. **Nothing guards public env.** Its values go to the browser (payload, static export). A
     `public: z.object({ STRIPE_SECRET_KEY })` passes every check.
  3. **The framework's own variables are scattered:** `PORT`, `HOST`, `SESSION_SECRET`, `NODE_ENV` and
     `HOZU_TRANSFORM_CACHE`.
  4. **No list of what to set:** there is no `.env.example`, and no way to see which values are missing.
  5. **One API, two addresses.**
     - The browser calls the public URL, `https://api.example.com`.
     - A server in the same network should call the internal one, `http://api.internal:8080`, with no TLS, no load
       balancer and no egress.
     - `runs: 'server'` resolvers can already read a server variable. An `'either'` effect cannot: the same fetch.ts
       runs on both sides and receives only the public env, so server rendering goes out and back in.

## Decision
1. **`env.files`:** `project({ env: { files: ['.env', '.env.local'], server, public } })` names the files to read,
   relative to the config.
   - **Who reads them:** the CLI (`dev`, `serve`, `check`, `get`, `call`, `browse`, `build`, `env`) reads them
     with Node's `process.loadEnvFile`, with no dependencies.
   - **Precedence:** a later file wins over an earlier one, and the shell wins over every file.
   - **Missing files** are skipped.
   - **Explicit:** the list is in the config; nothing is read by convention. New apps get
     `['.env', '.env.local']`. `createHandler` on the edge reads no files: there the platform sets the environment.
2. **HZ084 `public-secret` (warning):** a public variable whose name looks secret (`SECRET`, `TOKEN`, `PASSWORD`,
   `PRIVATE`, `CREDENTIAL`, or a `KEY` that is not `PUBLISHABLE`).
   - The message says it is sent to the browser.
   - **The fix:** move it to `server`, or rename it with a `PUBLIC_` prefix when it is meant to be public.
3. **`hozu env [--example] [--json]`:** lists every variable with its side (server or public), whether it is
   required, its default, whether it is set now (after the files), and its internal mapping.
   - `--example` writes `.env.example`: names, comments, and public defaults only.
4. **`hozu docs env`:** the framework's reserved variables, and what each deployment reads (Node, edge, static
   export).
5. **`env.internal`:** `{ PUBLIC_NAME: 'SERVER_NAME' }`.
   - **On the server:** an `'either'` effect's fetch.ts reads `env.PUBLIC_NAME` as the server variable's value
     when that is set, and the public value otherwise.
   - **In the browser:** always the public value. The internal value is a server variable, so it never reaches
     the payload, a page or a static export.
   - **CSP `connect`** uses the public value.
   - **HZ085 `invalid-env-config` (error):** the key is not a public variable, or the value is not a server
     variable.

## Options considered
- **The same name in both schemas means "internal on the server".** Rejected: shorter, but implicit.
- **Reading `.env` by convention**, without `files`. Rejected: principle 2 (explicit over implicit), and an agent
  should see which files count.
- **Per-mode files** (`.env.production`). Not done: the deployment platform owns the environment.
- **A `PUBLIC_` prefix rule** for every public variable. Rejected: the schemas already separate the two sides.
  The prefix is only the way to say "public on purpose" to HZ084.

## Migration
0.12 → 0.13 rewrites nothing. The IR's `env` gains `files: []` and `internal: {}`, which the step adds before
comparing. Apps opt in by adding `files`.

## Result
- **Shipped in 0.13.0.**
  - New apps list `['.env', '.env.local']` and ignore both.
  - Added after review: **HZ086** (a listed env file git would commit).
- **Measured:**
  - The trial app's required server variable in `.env.local` works with `check`, `get` and `call`.
  - `check` passes without it.
  - `'either'` server rendering follows `env.internal`, and no internal value reaches a page.
- **The trial found:**
  - the CLI checked app bindings without the env (fixed: it passes the env, and check retries without parsing it);
  - `testApp` needs `env` passed (documented).
- **Not done:** HZ084 stays a warning (owner). Browser-held data declared `scope: 'public'` is left to the guide.
