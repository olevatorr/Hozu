# ADR 0024 — Render functions generated as JavaScript source

- Status: proposed
- Motivation: after ADR 0023, SSR renders 35 k pages/s in the framework benchmark; Svelte renders 94 k. ADR 0023
  names generated render functions as the next lever, and requires them to be edge-safe.

## What the measurements show
**Profile of `bench/frameworks/ssr-only.ts` (inclusive time):**

| Part | Share | What it is |
|---|---|---|
| `sync`: compiled closure fragments for subtrees that do not suspend | 58% | Includes island opening (11%, of which `pruneScope` 7%) and garbage collection from copying the `Scope` object per `each` item |
| `payloadJson` | 19% | Mostly the island scopes |
| Page, head and data runtime | the rest | |

**Prototype.** The product list (100 items, 100 islands) was written by hand as the code a generator would emit:
- direct property reads (`b1?.name`) instead of getter closures;
- `out +=` string concatenation;
- a local variable per `each` level instead of a copied scope object;
- the island scope JSON written inline, since its shape is known at compile time.

| | µs per render of the list |
|---|---|
| Closures (today) | 17.1 |
| Generated code | 7.2 |

The generated code is **2.4× faster**, with the same HTML. Applied to the whole page, this predicts about 17.5 µs
instead of 27.5 µs per render: **about 55 k renders/s**.

## Decision 1 — Where the code is generated
| Option | Trade-off |
|---|---|
| a. `new Function` at server start | Simple, but **Cloudflare Workers and other edge runtimes forbid eval**, which breaks ADR 0016's edge support |
| b. Generated by `tenon build`; the closure compiler stays for dev and tests | Two render paths that must stay byte-identical; tests exercise the one production does not use |
| **c. One generator, and generated code is the only render path** | The source text is produced by one function. `tenon build` writes it to `dist/server/render.js`. Without a build (Node dev, tests, `node serve.ts`), the server generates the same text at startup and imports it as a `data:` module. The closure compiler is deleted |

**Decision (c).** There is one path, and every test runs the code production runs.
- On a runtime that cannot import generated source, `createHandler` without a generated `render` module fails at
  startup with a structured error saying to run `tenon build` and pass the module. It never silently falls back.
- `examples/cart/edge.ts` imports the module explicitly (principle 2), and the web-only vm check and the Bun check
  cover it.

## Decision 2 — What is generated
- **One function per (route, node, island flag),** for every subtree that does not suspend. That is the granularity
  of today's closure cache: a node renders differently depending on whether the route makes it an island.
- **Suspending structure stays interpreted.** That is `ui.query` and the elements, branches and loops that contain
  one: the async renderer in `render.ts` still streams in order and flushes before awaiting.
  - In the profile, the code between suspension points is where the time goes; the few suspension points
    themselves cost little.
  - Generating async code is a possible later step if a profile shows the interpreter.
- **Island opening is generated too.** The scope projection that `pruneScope` computes at runtime is known per node
  at compile time, so the generated code writes the island's scope JSON directly into the payload run.
- **`fn` implementations and locale-dependent helpers are parameters of the generated functions,** not free
  variables. The same module serves every locale.
- **The image transform (`responsive`) runs before generation,** because the image variants are known at build
  time and at server start.

## Decision 3 — Safety of generated source
- **Every string that comes from the IR is embedded with `JSON.stringify`:** tag and attribute names, classes,
  literals, ids, event names. Nothing is concatenated into code unquoted.
  - The vocabulary is already closed and validated (TN027, TN031). The quoting still holds if validation missed
    something.
- **The generated module imports nothing.** Helpers (`escapeHtml`, `text`, `attrText`, class and style text) are
  passed in, so a `data:` import needs no module resolution.
- **A test tries to break out:** IR literals containing quotes, `</script>`, backticks, `${` and line separators must
  come out as the same text in the HTML.

## Decision 4 — Equivalence while migrating
- **Before the closure compiler is deleted,** a differential test renders every page of every example (all locales,
  with and without images, as islands and not) both ways, and requires **byte-identical HTML and payload**.
- **After deletion,** the committed render tests and parity (24/24) guard the output.

## Principle check
- **Principle 1:** one render path.
- **Principle 2:** an edge server imports its generated module explicitly.
- **Principle 8:** the render plan decides what is generated, as it decides what hydrates.
- **Authoring surface:** unchanged, so the AI trials are unaffected.
