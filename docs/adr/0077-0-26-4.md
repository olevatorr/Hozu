# ADR 0077 — 0.26.4: a mismatch stops the check, and a shortcut inside a dialog is its own

- **Status:** accepted (owner, 2026-10-09: "Ok都照你建議").
- **Evidence:** round 8 of trial 0025 (admin and storefront, 0.26.2 → 0.26.3). Both upgraded by the printed `next:`
  lines alone and ended with a clean `hozu check`, the first unassisted patch upgrade of the trial. The storefront's
  image held no `.env`, no `.git` and no host `node_modules`. What remained: a CLI / core mismatch still printed 216
  and 3 449 lines of false diagnostics under its warning; HZ014 refused one `/` in the mobile menu's `<dialog>` and one
  in the header, which the runtime allows; and smaller wording.
- **Judged as before:** whose problem, which principle.

## Accepted
| # | Ask (source) | Decision |
|---|---|---|
| A1 | HZ014 counts a control inside a `<dialog>` as always shown with the page (store) | A bug: the runtime counts only an open modal's own controls, and a closed dialog's controls are hidden. The check walks a `dialog` as its own scope: two controls inside it still clash, one inside and one outside do not. A popover stays in the page's scope: it is not modal, so the runtime sees both controls (review) |
| A2 | A mismatch still prints every diagnostic (both) | `hozu check` stops before loading the app: a `config` error naming both versions, with no diagnostics. They would all come from the difference (principle 7: say nothing false) |
| A3 | The fix says `migrate` after migrate already ran (store) | The fix follows the state: `package.json` already names this CLI's version → `npm install`; the app is older → `npx hozu migrate`; the app is newer → `npx -p @hozu/cli@<core> hozu check` |
| A4 | What migrate did itself is listed under `by hand:` (both) | `MigrateOutput.done` lists it under `done:`; `by hand:` keeps only what the person must do |
| A5 | An older `migrate-0.23.json` stays (admin) | Every record of an older minor is removed (under `done:`); a newer minor's record waits for its own CLI (review) |
| A6 | The upgrade does not refresh the agent guide (store) | Phase `upgrade` writes the guide from this CLI's copy, as `verify` does |
| A7 | `press r` where no control has `r` says nothing (admin) | `no control has r`, unless the key types into the focused field or is a named key (Tab, Enter, Escape, arrows…) |
| A8 | Without JS, `press Escape` says "a shortcut needs JavaScript" though no control has Escape (store) | Only a key some control declares is a shortcut; another key says it has no native action |
| A9 | `docker build -f ../../../../../tmp/…` and `-t app` (store) | A path that leaves the current folder is printed absolute; the image is named after `package.json`'s `name` |
| A10 | `.claude` and `CLAUDE.md` reach the image (store) | The generated ignore file lists `.claude`, `.agents`, `CLAUDE.md`, `AGENTS.md` |

## From the review before the tag
- The mismatch fix reads `devDependencies` too, accepts `^` / `~` / exact ranges, and names the app's own package
  manager; `installCommand` moved to `versions.ts`.
- Browse: Shift with a named key and F1–F12 / Insert are not "no control has"; inside an open modal the note says
  "no control in the open dialog has"; without JS Shift+Tab is native, Escape is native while a dialog or popover is
  open, and Shift+X falls back to X.
- `docker build` paths with a space are quoted; image names follow Docker's component rule; the runtime looks for
  shortcuts in the innermost open modal.

## Declined
| Ask | Why not |
|---|---|
| `press` saying `focus on <body>` when nothing had focus before or after (admin) | Focus leaving an element is already reported; a line on every press where nothing changed is noise |
| A Dockerfile or compose file for the Go service (admin) | How a service builds is the app's own; a template would be a guess |
| A global notice store; `app(({ env }))`, more machines per feature, kit components taking data objects | Unchanged reasons (ADR 0069 C, ADR 0070 B4, ADR 0075); the store "will no longer pursue" them |
