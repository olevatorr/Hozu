# ADR 0072 — 0.25: what mainstream frameworks do, at Hozu's cost

- **Status:** accepted (owner, 2026-10-08: "我覺得就是要做到主流框架做得到的體驗，但也要有主流框架做不到的效能和Ai體驗來下去評估",
  then "全部都放進0.25一次做好").
- **Evidence:** the 0.24 retest of the storefront and the admin, a smoothness sweep of the examples with `hozu browse`
  (feed, watchlist, cart, bookmarks), and the "Later" lists of ADR 0064 and ADR 0067.
- **How each item was judged:** three questions. Does a person using a React / Vue / Svelte app get this without
  the author asking (parity)? Does Hozu keep its lead in bytes and work done (performance)? Can an agent find and
  verify it cheaply (AI)? Then: whose responsibility it is, and the principle it touches.

## A. A branch that keeps its element (parity)
`c ? ui.button(…, ['Resume']) : ui.button(…, ['Pause'])` rebuilds the button whenever `c` changes. React and Vue
keep the element and patch its text and listener: focus stays, nothing flashes, and screen readers do not announce a
new control. Hozu loses focus on every such toggle (a keyboard user's Pause button drops them to `<body>`).

**Options.**
1. Merge at record time into one element whose values are `%cond`. Every IR consumer (validator, lock, why,
   DevTools, forms) would have to understand a conditional send. Rejected: the IR stops saying "two controls".
2. Morph the DOM at runtime (adopt the old element for the new branch). A VDOM-shaped piece of code in the client;
   does not fit P7.
3. **Chosen:** the renderers merge. `renderBuild(build)` in `@hozu/runtime-server` (memoized per build, applied by
   `createHandler`, `generateRender`, `renderPage` and `fnModules`) replaces such an `if` with one element when both
   branches have the same shape, the way `lower.ts` already prepares nodes for a locale. The IR keeps `ifTrue` /
   `ifFalse` for every analysis (validator, lock, contracts, `hozu why`, DevTools), so nothing a person reviews
   changes, no IR field is added and `hozu migrate` has nothing to map. The server and the client render the merged
   element, so it is written once and bound once.

**When branches merge.** No motion; each branch is exactly one element with the same tag (and the same component, for
a pure use); every child pairs with a child of the same kind: an element (merged the same way) or a text. Not
`form`, `dialog`, `input`, `select`, `textarea`, `img` or `option` (form state, native posts and image sizing stay on
the branch), no `ref`, no `visible` event that differs.

**How.** A value both sides share stays as it is; one that differs is `%cond(test, a, b)` (an absent attribute is
`null`, an absent toggle `false`). Classes keep their common tokens static and move the rest into toggle groups
guarded by the test and its negation, so the Tailwind candidates do not change. A listener that differs is a pick:
`{ test, a, b }` of the two sends (or `null`), read when the event fires. `%cond` evaluates both sides, so a
value that differs and computes (a `fn`, an operator) keeps the two branches: `ctx.picked !== null ? title(ctx.picked)
: 'Pick one'` must not call `title(null)`. Links whose targets differ keep them too, so `aria-current` stays derived
from a link. DevTools names the merged element by the true branch's node (file:line). Ids are the true branch's, and the
build registers `%cond` when it merged anything.

## B. Keyboard shortcuts (parity)
`ui.window({ on: { keydown: ui.send(Open, { key: ui.dom.key }) } })` sends every key press to the machine and cannot
stop the browser's own shortcut (Cmd+K focuses the address bar). **Chosen:** `ui.send(Event, payload, { keys })`:
- `keys` is a list such as `['Mod+k', '/', 'Escape']`. `Mod` is ⌘ on Apple platforms and Ctrl elsewhere; the
  modifiers are `Mod`, `Ctrl`, `Meta`, `Alt` and `Shift`; the key is `KeyboardEvent.key`, case-insensitive for letters.
- Only on `keydown` / `keyup`. A send with keys fires only on a matching press and calls `preventDefault()`.
- A printable key without `Mod`, `Ctrl`, `Meta` or `Alt` does not fire while the person types in a field (an input,
  textarea, select or contenteditable element) inside the listening element or window, so `/` still types a slash
  there; `Escape`, `Enter` and the other named keys still fire. Nothing fires while an input method composes (IME),
  and an Alt combination also matches the physical letter (macOS turns Alt+k into "˚").
- A bad key list is HZ014 with the grammar. Focusing an element is not a shortcut's job: a dialog `showModal()`s
  focus itself, and `autofocus` covers a field shown by a state.

## C. Modes belong in the context (guide)
The watchlist swapped Resume / Pause while adding from paused. That is not a missing feature: "paused" is a mode
that has nothing to do with saving, and a machine state can only be one thing at a time. A mode the person sets
lives in the context (`ui.set('paused', true)`), and the busy states keep it. `examples/watchlist`, the recipe and
`hozu docs machine` say so. ADR 0067's "a mode that busy states inherit" is declined: parallel states would be a
second way to hold the same fact.

## D. Performance stays ahead
| # | Item | Decision |
|---|---|---|
| D1 | P7 has 7 bytes left (9 209 / 9 216 B) | Keep 9 KiB. Code that few pages need moves into the lazy chunks the page loads when it has such a node (the machine-bound dialog first), so A and B fit |
| D2 | Smoothness is reported but not kept | **New budgets S1 / S2:** each example with a machine has `browse.json`, the steps a person takes (blog, bookmarks, cart, feed, notes, showcase, stations, studio, watchlist; not notes-go, which needs its Go service, stars and playground, which call public APIs (a bench must not depend on the network; 0.26.1 dropped playground after a failed fetch), or the frozen trial apps). `pnpm bench` runs them through `bench/smooth.ts` with JavaScript on and requires no element rebuilt unchanged (S1 = 0) and no step's layout shift above 0.01 (S2); a failed step fails the budget. Mainstream frameworks have no such budget; it makes "no flash" a checked claim |
| D3 | Soft navigation stays declined (ADR 0043 I) | Measured instead: `hozu browse` names how a navigation arrived and its time from activation to the first contentful paint (`→ /products/mug (loaded, 32 ms)`). Chrome disables prerendering under DevTools request interception (ADR 0043), so browse measures the worst case, a document load from the in-process handler without prerender; a real visitor's prerendered page activates already painted |

## E. Tools and guide (AI)
| # | Ask (source) | Decision |
|---|---|---|
| E1 | A click that lands on another element passes silently (store: card overlay on `h3::after`) | **Accepted.** `hozu browse` checks the topmost element at the click point; when it is neither the target nor inside it, the step fails: `the click landed on h3 (or its ::before / ::after), above a[href=/products/…]` |
| E2 | `current(route)` cannot mark "Apparel" (store) | **Accepted:** `current(route, params)` compares the given params with the page's and ignores search. A params key the route does not have is HZ007. The page's params reach the render through a new reference, `here` (the server's scope and the client read the page's params, which the payload already carries) |
| E3 | `current(a, b)` or route groups (admin) | **Declined.** `current(a) \|\| current(b)` already says it, and route groups would be a second name for a section. The guide shows the nav as a constant list mapped to links, which keeps each section on one line |
| E4 | "`\|\|` runs at record time inside `.map`" (admin) | **Not so:** `current()` returns a reference, so `\|\|` lowers to `%cond` inside a constant `.map` too (checked). The guide shows that form |
| E5 | The first `migrate` printed an empty change list (admin) | **Not a bug:** the bullets were printed; the run filtered them with `grep "→\|rewrote\|next"` |
| E6 | `--select` hides `class` (store) | **Accepted:** `hozu get --select` / `browse --select` print `class` with the element |
| E7 | The feed's Load more was reported as a flash | **Tool fix:** the button moved from page 1's section to page 2's. An element that leaves a parent that stays and appears under another parent moved; it is not counted |

## F. Declined
| Ask | Why not |
|---|---|
| A draft that survives a reload, built in (ADR 0064 Later) | Mainstream frameworks do not do it either; a recipe shows the client component (`localStorage`) |
| `ui.format.ago` that updates by itself (ADR 0064 Later) | Same; `freshness: { poll }` or a client component, in the recipes |
| Server-rendered kept state (ADR 0067 Later) | It needs the state in a cookie on every request; the kept state is a convenience, not data |
| A diagnostic for "expectable" thrown errors (admin) | Guessing from message text is a heuristic that would misfire; the guide already draws the line |
| Checking the Go service at `hozu dev` / `serve` start (admin) | Not in this release: the 409 names the effect; revisit with the next Go trial |
| A global toast store (admin) | Out of scope by principle (no global mutable client stores); the recipe "A notice after saving" stays |
